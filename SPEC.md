# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## AI News Rewriter

Версия: 1.0
Тип проекта: Desktop + Server (headless-режим)
Язык разработки: Python 3.12+
Интерфейс: PySide6 (Qt)
Платформа: Windows / Linux
Режим работы: 24/7

---

## 1. Цель проекта

Разработать программное обеспечение, которое автоматически отслеживает выбранные пользователем Telegram-каналы и VK-сообщества, отбирает только новостные публикации, выполняет их полный рерайт с помощью локальной языковой модели, оформляет изображения фирменным watermark и автоматически публикует готовые посты в Telegram и VK по заданному расписанию.

Программа должна работать полностью автоматически после первоначальной настройки.

Важно: программа **не ищет новости в интернете** и **не парсит произвольные изображения из поисковой выдачи**. Источники — конкретные Telegram-каналы и VK-сообщества, выбранные пользователем. Изображения — либо из самого поста, либо через легальные API стоковых библиотек (Unsplash/Pexels/Pixabay), либо локальная генерация ИИ.

## 2. Основная идея

Пользователь один раз настраивает систему. После этого программа:

- отслеживает выбранные источники;
- анализирует новые публикации;
- фильтрует ненужный контент;
- переписывает текст;
- подготавливает изображения;
- публикует материалы.

Без участия пользователя.

## 4. Общая схема работы

```
Telegram каналы
      +
VK сообщества
      │
      ▼
Получение новых постов
      │
      ▼
Фильтрация (стоп-слова / whitelist / реклама / дубли)
      │
      ▼
Классификация LLM (score 0–100)
      │
      ▼
LLM Rewrite (текст + заголовок)
      │
      ▼
Подбор изображений (пост → сток-API → локальная генерация)
      │
      ▼
Watermark
      │
      ▼
Очередь публикации (по расписанию)
      │
      ▼
Telegram / VK
```

## 5. Основные возможности

- Чтение Telegram-каналов и VK-сообществ.
- Запоминание уже обработанных публикаций (без повторной обработки).
- Защита от дублей (по `external_id` и по SimHash текста).
- Определение рекламных и не новостных публикаций.
- Полный рерайт текста через локальную LLM.
- Редактируемые пользователем промпты (без хардкода в коде).
- Watermark на изображениях.
- Легальный подбор изображений (сток-API / генерация).
- Автопубликация по расписанию.
- Круглосуточная headless-работа на сервере.

Главное окно, меню слева:

🖼 Изображения
📤 Публикация

### 6.1 Главная страница

Отображает: статус (работает/остановлено), время последней/следующей проверки, число новых постов, число опубликованных сегодня, число ошибок.

Кнопки: Запустить / Остановить / Проверить сейчас.

### 6.2 Источники

Две вкладки: Telegram и VK. Поля источника: название, ссылка, приоритет (0–10), вкл/выкл. Кнопки: Добавить / Удалить / Редактировать / Проверить.

## 7. Мониторинг источников

Каждые `check_interval_minutes` (по умолчанию 240 = 4 часа) программа:

1. Получает новые публикации из каждого включённого источника.
2. Отбрасывает публикации старше `max_post_age_hours` (по умолчанию 24ч).
3. Отправляет новые публикации в модуль фильтрации.

## 8. Фильтрация

Последовательный конвейер фильтров:

```
Получение поста
   → Новость? (не реклама/не конкурс/не продажа/не вакансия/не опрос/не закреп)
   → Есть ключевые слова из белого списка? (бонус к приоритету)
   → Нет стоп-слов из чёрного списка?
   → Не дубль? (external_id + SimHash текста)
   → Классификация LLM (score)
   → score >= min_score?
   → Rewrite
```

Любой пост, не прошедший фильтр, попадает в таблицу `rejected_posts` с указанием причины — не удаляется физически.

### 8.1 Стоп-слова (примеры, редактируются пользователем)

скидка, промокод, акция, купить, заказать, партнёрский материал, реклама, интеграция, переходите по ссылке, подписывайтесь, розыгрыш, конкурс.

### 8.2 Белый список (приоритетные темы, примеры)

Россия, Москва, Кремль, Путин, Президент, Правительство, Госдума, Армия, Минобороны, Экономика, Санкции, Рубль, Доллар, Нефть, Газ, НАТО, США, Европа, Китай, Закон, Суд, МВД, ФСБ, МЧС, Катастрофа, Происшествие.

Оба списка полностью настраиваются пользователем через UI и `config.yaml`.

## 9. LLM (Gemini API по умолчанию, опционально Ollama)

### 9.1 Требования

- Два провайдера за одним интерфейсом (`LLMClient`, `app/core/llm/client.py`), переключаются через `llm.provider` в `config.yaml`:
  - **`gemini`** (по умолчанию) — облачный Gemini API, бесплатный tier, нужен `GEMINI_API_KEY` в `.env` (https://ai.google.dev/). Не требует VPS/RAM-ресурсов — подходит для слабых машин и дешёвых хостингов.
  - **`ollama`** — локальная LLM через HTTP API (`http://localhost:11434`), для тех, у кого есть 8 ГБ+ RAM и они хотят полностью офлайн-решение.
- Модель настраивается (`llm.model`): для Gemini — `gemini-2.5-flash` (по умолчанию — на `gemini-2.0-flash`/`gemini-2.0-flash-lite` бесплатная квота может быть нулевой в зависимости от проекта, проверять через `GET /v1beta/models`) или другие модели Gemini; для Ollama — `qwen2.5:3b`/`qwen2.5:7b`/`llama3.1:8b`/`gemma2:9b` и т.д.
- Gemini API из РФ напрямую недоступен (гео-блок датацентр/VPN-диапазонов Google) — нужен residential/мобильный прокси (`GEMINI_PROXY_URL` в `.env`, SOCKS5/HTTP). `LLMClient` подхватывает его автоматически для всех Gemini-запросов, не затрагивая остальные интеграции.

### 9.2 Проверка доступности при старте

1. Для Gemini: проверить, что `GEMINI_API_KEY` задан и API отвечает на список моделей. Для Ollama: проверить, что сервер запущен (`GET /api/tags`).
2. Для Ollama дополнительно — проверить, что выбранная модель скачана; если нет — кнопка "Скачать модель" (`ollama pull`) с прогрессом. Для Gemini скачивание не требуется (облачная модель).
3. Если провайдер не настроен (нет ключа/сервера) — инструкция в UI, без автоустановки в фоне.
4. Если LLM недоступна — обработка приостанавливается, статус `⛔ LLM недоступна`.

### 9.3 Клиент LLM

Единый внутренний класс `LLMClient`:

- собирает system-промпт + user-промпт;
- параметры `temperature`, `top_p` из настроек;
- `timeout` по умолчанию 60с, 1 retry, затем пост помечается `failed`;
- логирует каждый запрос/ответ в `logs/llm.log` с ротацией (10 МБ).

Одна операция = один вызов LLM (классификация, рерайт, заголовок — отдельно, не один "супер-промпт").

## 10. Система промптов

### 10.1 Структура

```
/prompts
    system.txt          — базовая личность и стиль (общий)
    classifier.txt       — новость/не новость + оценка
    rewrite.txt           — полный рерайт текста
    headline.txt          — генерация заголовка (2–3 варианта)
    fact_check.txt        — базовая проверка на признаки фейка
    image_query.txt       — поисковый запрос для картинки
    style_official.txt    — модификатор стиля: официальный
    style_viral.txt        — модификатор стиля: вирусный
    style_short.txt        — модификатор стиля: короткий
```

Плейсхолдеры: `{{TEXT}}`, `{{SOURCE}}`, `{{STYLE}}`, `{{KEYWORDS}}`.

### 10.2 Редактируемость

Все промпты редактируются из UI (вкладка "ИИ → Промпты") без перезапуска программы; хранятся как обычные `.txt`-файлы, не в коде.

### 10.3 Анти-ИИ требования к рерайту (встраиваются в `system.txt`)

- без канцелярита, без "более того", "стоит отметить";
- без тройных перечислений подряд, без шаблонных вводных конструкций;
- живой разговорный язык;
- избегать одинаковой структуры предложений подряд.

### 10.4 Порядок вызовов LLM на один пост

```
1. classifier.txt   → оценка (0–100) + категория + причина отклонения
2. rewrite.txt       → переписанный текст          (только если score прошёл порог)
3. headline.txt      → 3 варианта заголовка
4. image_query.txt   → поисковый запрос для картинки (если своих фото нет)
```

### 10.5 Формат ответа классификатора (строгий JSON)

```json
{
  "is_news": true,
  "category": "политика",
  "score": 87,
  "reasons": ["высокая новостная ценность", "затрагивает РФ"],
  "reject_reason": null
}
```

При невалидном JSON — одна повторная попытка; при повторной ошибке — статус `error_classification`, пост не блокирует очередь остальных.

## 11. Оценка постов (скоринг)

| Компонент | Вес | Источник |
|---|---|---|
| Новостная ценность | 35% | оценка LLM |
| Совпадение с белым списком | 25% | локальная проверка |
| Просмотры источника | 20% | метаданные поста |
| Свежесть | 10% | возраст поста |
| Приоритет источника | 10% | настройки источника |

Порог публикации по умолчанию: `min_score: 75` (настраивается 0–100).

## 12. Обработка изображений

### 12.1 Приоритет источников

1. Изображения из самого поста (если есть).
2. Легальные сток-API (Unsplash / Pexels / Pixabay) по официальному ключу.
3. Локальная генерация ИИ (Stable Diffusion или сравнимый локальный движок) как альтернатива.

Прямой парсинг произвольных изображений из поисковой выдачи — **исключён** из-за юридического риска нарушения авторских прав.

### 12.2 Интерфейс `ImageProvider`

```
ImageProvider (interface)
    search(query: str, count: int) -> List[ImageResult]

  ├── SourceImageProvider     — фото из самого поста
  ├── UnsplashProvider
  ├── PexelsProvider
  ├── PixabayProvider
  └── LocalAIImageProvider    — локальная генерация
```

Провайдеры включаются чекбоксами, порядок приоритета задаётся пользователем.

### 12.3 Watermark

Модуль `Watermarker`:

1. Приведение к целевым пропорциям (1:1, 4:5, 16:9, 9:16 — под соцсеть).
2. Наложение логотипа (PNG с альфа-каналом), угол/прозрачность/отступ настраиваются.
3. Опционально — текст названия канала (шрифт/размер/цвет настраиваются).
4. Сохранение в `/output/images/{post_id}/`.

Уникализация фото (кроп 1% + гауссов шум + удаление EXIF) — добавлена 2026-07-02 по явному решению пользователя (изначально была исключена как юридически рискованная, инвариант отменён). Настраивается через `images.uniquify` в config.yaml, по умолчанию `enabled: true`.

## 13. Очередь публикации

### 13.1 Жизненный цикл поста

```
new → filtering → classified → rewritten → image_ready → queued → published
                        ↓                                      ↓
                    rejected                                 failed
```

Каждый переход статуса логируется в `post_history`.

### 13.2 Расписание

Режимы: фиксированные слоты (например 09:00, 13:00, 18:00, 21:00) либо интервал (например "не чаще раза в 40 минут"), плюс лимит публикаций в сутки. Планировщик берёт из очереди пост с наивысшим score на каждый слот; пустой слот — пропускается без ошибки.

### 13.3 Публикация

- **Telegram**: `python-telegram-bot`/`aiogram`, `sendPhoto`/`sendMediaGroup`, caption с учётом лимита в 1024 символа.
- **VK**: VK API (`wall.post`, `photos.getWallUploadServer` → `photos.saveWallPhoto`).

### 13.4 Обработка ошибок публикации

3 попытки с экспоненциальной задержкой (5с, 30с, 120с); после исчерпания — статус `failed`, уведомление в UI и логе, пост остаётся в очереди для ручной публикации. Обход лимитов соцсетей не рассматривается.

## 14. Хранение данных (SQLite)

```
sources        (id, type[tg/vk], name, url, priority, enabled)
raw_posts      (id, source_id, external_id, raw_text, media, fetched_at)
processed_posts(id, raw_post_id, score, category, rewritten_text,
                headline, status, created_at, published_at)
post_history   (id, post_id, status, timestamp, note)
rejected_posts (id, raw_post_id, reason, score, created_at)
settings       (key, value)
```

Дедупликация: по `external_id` источника + по SimHash/MinHash нормализованного текста (порог схожести настраиваемый, по умолчанию 85%).

## 15. Конфигурация (`config.yaml`)

```yaml
app:
  name: "AI News Rewriter"
  language: "ru"
  timezone: "Europe/Moscow"

llm:
  provider: "gemini"
  host: "http://localhost:11434"  # используется только при provider: "ollama"
  model: "gemini-2.5-flash"
  api_key_env: "GEMINI_API_KEY"   # используется только при provider: "gemini"
  temperature: 0.7
  top_p: 0.9
  timeout_seconds: 60
  retries: 1

monitoring:
  check_interval_minutes: 240
  max_post_age_hours: 24
  fetch_batch_size: 50

sources:
  telegram: []
  vk: []

filters:
  min_score: 75
  duplicate_similarity_threshold: 0.85
  min_views: 500
  stop_words: []
  required_keywords_boost: true
  whitelist_keywords: []
  blacklist_keywords: []

scoring:
  weights:
    news_value: 0.35
    keyword_match: 0.25
    source_views: 0.20
    freshness: 0.10
    source_priority: 0.10

rewrite:
  style: "viral"
  max_length_chars: 900
  headline_variants: 3

images:
  providers_order: ["source", "unsplash", "pexels", "pixabay"]
  count_per_post: 3
  target_aspect_ratio: "4:5"

watermark:
  logo_path: "assets/logo.png"
  position: "bottom-right"
  opacity: 70
  margin_px: 24
  channel_name_text: true

publishing:
  targets:
    telegram:
      enabled: true
      bot_token_env: "TG_BOT_TOKEN"
      chat_id: "@my_channel"
    vk:
      enabled: true
      token_env: "VK_GROUP_TOKEN"
      group_id: 0
  schedule:
    mode: "fixed_slots"

    interval_minutes: 40
    max_posts_per_day: 12

logging:
  level: "INFO"
  max_file_size_mb: 10
  backup_count: 5
```

Секреты (токены, API-ключи) — только через `.env`, никогда в `config.yaml`. Отсутствие обязательной переменной при старте — явная ошибка, а не тихий пропуск.

### Архитектурные инварианты (нельзя нарушать)

- `ui/` не содержит бизнес-логику — только вызовы `core/*` и отображение.
- `core/*` не знает о Qt/PySide — переиспользуемо и тестируемо отдельно.
- Доступ к БД — только через `db/repository.py`, никаких прямых SQL из `core/`/`ui/`.
- Каждый `ImageProvider` и `Publisher` — отдельный класс за общим интерфейсом (легко добавить новую соцсеть, не трогая существующий код).

## 19. Развёртывание

### 19.1 Локальный запуск

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env  # заполнить GEMINI_API_KEY (https://ai.google.dev/) и остальные секреты
python app/main.py
```

### 19.2 Headless-режим (сервер)

```bash
python app/main.py --headless
```

`systemd` unit (Linux) и/или Docker Compose (`app`, опционально `ollama` через `--profile ollama`) — секреты только через env-file, не в образе.
