## Открытый вопрос — единственный источник может простаивать

`novosti_efir` — единственный активный источник (по прямому запросу
пользователя). Ночью 2026-07-05 он не постил 4.5 часа подряд — за это время
пайплайн физически нечего публиковать, это не баг. Если "12 постов/день"
не набирается стабильно из-за пауз канала — решение: вернуть `toporlive`/
`novosti` как резервные источники (они уже в БД, просто `enabled=0` — id 1 и
7). Не включать самостоятельно без явного запроса пользователя.

## Известные грабли, добавленные в этой сессии (не наступать снова)

- **Один цикл `check_interval` = один вызов `run_check_cycle` + сразу
  `pick_next_post_to_publish` в той же корутине** — если фетч ЛЮБОГО источника
  кидает необработанное исключение, публикация в этом цикле не произойдёт
  вообще, даже если источник, который упал, никак не связан с тем, что должно
  публиковаться. Каждый источник в цикле теперь обёрнут в try/except
  отдельно — если снова добавляешь фетчер, не забудь то же самое.
- **Скачивание медиа до дедупликации — путь к раздутию диска.** Если
  добавляешь новый фетчер с медиа, сначала фильтруй по `known_external_ids`,
  потом скачивай — не наоборот.
- **`vk_api` сериализует Python `bool` в `"True"`/`"False"`, не в `"1"`/`"0"`**
  — VK API не может это распарсить. Если видишь непонятную ошибку VK на новом
  методе — проверить типы параметров первым делом.
- Раздельный `_upload_to_server`/`saveWallPhoto`-ответ VK на `photo` может
  содержать вложенный JSON-массив строкой — это нормально, не баг, просто
  формат VK.
