## Осталось для реального использования нового функционала

- **`.env` этой машины ещё не заполнен** новыми переменными `NATURE_BOT_PATH`,
  `SHORTS_PATH`, `SHORTS_BASE_URL` (см. `.env.example`) — без них команды
  `/nature_*`/`/shorts_*` отвечают "не настроен", а не падают (это ожидаемо),
  но реально ничего не запустят. Вписать перед первым использованием этих
  команд в проде.
- **Живой прогон через сам Telegram control-бот не делался** — команды
  протестированы юнит-тестами и напрямую через Python-скрипты (реальные
  subprocess/HTTP, не моки), но НЕ через реальный `/nature_run`/`/shorts <id>`
  в самом боте. Стоит один раз проверить после того как `.env` заполнен.
- **`/shorts <id>` не публикует сам** — только присылает готовое видео файлом
  в чат control-бота на проверку (осознанное сужение scope). Если пользователь
  захочет автопубликацию шортсов — отдельная явная задача.
- vk-nature-bot ждёт рабочий `VK_USER_TOKEN` (см. его собственный

## Открытые вопросы, требующие решения пользователя

- **"Старая новость" в опубликованном посте** — `monitoring.max_post_age_hours:
  168` (7 дней, коммит `c57eae4` от 07-01, сознательное решение для объёма 12
  слотов/день) означает, что реальное событие может быть до недели старше
  момента публикации. `RawPost` не хранит дату оригинального поста источника
  (только `fetched_at` — когда МЫ его скачали), поэтому свежесть не проверяется
  повторно на момент публикации, только один раз при приёме в очередь. Не
  исправлено — нужно решение пользователя: сузить окно обратно (меньше
  свежих постов, но не "старых") или оставить как есть ради объёма.
- **`uniquevid.ru`** (внешний сервис уникализации видео) — токен настоящий
  (проходит на `/api/v1/me`), но `/jobs`/`/presets`/`/account`/`/settings`
  отдают 401 тем же токеном — похоже на `subscription_active: false` при
  `credits_balance: 5` на их стороне, не проблема с токеном. **Пользователь
  попросил отложить** — не трогать без нового явного запроса. Если решится:
  сравнить их технику уникализации видео с нашей (`app/core/media/uniquifier.py`)
  и забрать то, что окажется лучше, для видео И фото.

## Известные грабли, добавленные в этой сессии (не наступать снова)

- **`vk_api` сериализует Python `bool` в строку `"True"`/`"False"`**, не в
  `"1"`/`"0"` — VK API не может это распарсить и падает generic-ошибкой
  (`[10] Internal server error`), которую легко принять за архитектурное
  ограничение. Если снова видишь непонятную ошибку VK на каком-то методе —
  сначала проверить, не передаётся ли где-то Python `bool` вместо `int`.
- **LLM повторяет структуру входного промпта в своём выводе** — если промпт
  показывает модели метаданные в формате "Ключ: значение" (например
  "Источник: {{SOURCE}}") как КОНТЕКСТ, дешёвые модели (`llama-3.1-8b-instant`)
  могут скопировать этот же формат в конец своего ответа. Нужна явная фраза
  "не включай это в результат", недостаточно просто не просить это явно.
- **Shorts API — префикс `/api/v1`, не голый путь из router.py**, и КАЖДЫЙ
  запрос требует заголовок `x-api-key` (даже пустой строкой) — иначе 401.
  Уже исправлено в `app/core/shorts/client.py::_auth_headers()`.
- **Shorts возвращает ОТНОСИТЕЛЬНЫЙ путь** в поле `videos`
  (`/tasks/{id}/final-1.mp4`), не полный URL, как в примере его же схемы —
  `client.py::_resolve_url()` достраивает до абсолютного перед скачиванием.
- Скрипт вне корня проекта (например, в scratchpad) — `load_dotenv()` без
  явного пути ищет `.env` от `__file__` скрипта вверх по дереву, НЕ от текущей
  директории (`os.chdir` не помогает) — если скрипт лежит вне репозитория,
  всегда передавать `load_dotenv(r"путь\к\проекту\.env")` явно.
